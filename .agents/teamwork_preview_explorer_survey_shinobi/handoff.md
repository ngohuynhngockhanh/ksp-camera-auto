## 1. Observation
- **Importer Package (`internal/importer/shinobi.go:20-51`)**: Existing parser extracts `mid`, `name`, `host`, `details.auto_host`, `details.muser`, `details.mpass`. It correctly handles stringified JSON in `details` via `parseDetails` and infers vendor (`VendorDahua` for `/cam/realmonitor`, `VendorHikvision` for `/Streaming/Channels`).
- **Config & Inventory (`internal/config/config.go:63-67`, `internal/config/inventory.go:40-187`)**: `Config` holds `Server`, `CamerasFile`, `Defaults`. It needs a `Shinobi` struct (`api_url`, `api_key`, `group_key`). `Inventory` provides thread-safe in-memory maps with mutexes and AES-256-GCM encryption on disk.
- **Server API & Routing (`internal/server/server.go:89-151`, `internal/server/api.go:144-159`)**: Routes are protected by session cookie `kspcam_session` and bounded by `limitBody(8<<20)`. JSON helpers `writeJSON` and `writeErr` are standardized.
- **Web UI Structure (`web/static/app.js:22-32`, `web/static/index.html:544-569`)**: Navigation is dynamically built from `NAV_ITEMS`. The current `#import` view supports manual JSON paste/upload and can be upgraded into a full `#shinobi` management view.
- **Shinobi REST API Endpoints**:
  - List monitors: `GET /:apiKey/monitor/:groupKey`
  - Get monitor: `GET /:apiKey/monitor/:groupKey/:mid`
  - Save/Configure monitor: `POST /:apiKey/configureMonitor/:groupKey/:mid` (form field `data=<json>` or JSON body)
  - Delete monitor: `GET /:apiKey/monitor/:groupKey/:mid/delete`
  - Change state: `GET /:apiKey/monitor/:groupKey/:mid/:state` (`start`, `stop`, `record`, `idle`, `restart`)
  - Video recordings: `GET /:apiKey/videos/:groupKey/:mid`

## 2. Logic Chain
1. *From observation of `internal/importer/shinobi.go`*: Shinobi represents camera connections as monitors with RTSP URLs and vendor-specific paths. Live APIs return details as escaped JSON strings. A dedicated `internal/shinobi` package can reuse this parsing logic and provide high-level abstractions.
2. *From observation of `internal/config/config.go` & `inventory.go`*: Storing `api_url`, `api_key`, `group_key` in `config.yaml` enables seamless client initialization without hardcoding credentials in Go code.
3. *From observation of RTSP streaming requirements*: Setting `vcodec: "copy"` and `record_vcodec: "copy"` ensures zero-transcoding CPU overhead on edge devices (Raspberry Pi/Orange Pi/Edge gateways) while recording streams.
4. *From observation of `internal/server/server.go`*: Adding REST endpoints (`/api/shinobi/status`, `/api/shinobi/monitors`, `/api/shinobi/sync`, `/api/shinobi/videos`) gated behind admin sessions provides complete control to the Web SPA and future MCP tools.
5. *From observation of test conventions in `internal/isapi/`*: A `MockShinobiServer` using `httptest.Server` enables 100% test coverage without external dependencies.

## 3. Caveats
- Shinobi NVR must be running and accessible over HTTP at the configured `api_url` (typically `http://127.0.0.1:8080`).
- The API Key generated by Ansible must have permissions for monitors and videos in the specified Group Key.
